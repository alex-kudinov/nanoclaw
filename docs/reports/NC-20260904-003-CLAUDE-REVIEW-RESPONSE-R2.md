# NC-20260904-003 — Claude review response R2

Reviewed only the packet and paths listed in the R2 request. No implementation file was edited.

## Material finding

**The R1 gap is closed in the conversational flow but reopened at the explicit-send alias layer: `mcs-foundation`'s registered `sendAliases` still contain the exact two bare terms the prompt itself calls out as forbidden to silently map, and because `mcs-foundation` has no required attributes, a matching explicit-send command executes same-turn with no disambiguation.**

- `groups/certifier/CLAUDE.md` now states: `Bare "MCS" or "Mentor Coaching Specialization" is now ambiguous... never silently map the bare program name to one of those three presets.`
- `presets.json`'s `mcs-foundation` entry lists `"sendAliases": ["mcs", "mcs foundation", "mentor coaching foundation", "mentor coaching specialization"]` — the first and last entries are the literal bare terms named as ambiguous in the prose guard above.
- The Dispatch table's Priority rule requires the Explicit campaign send grammar to be tested *before* New certificate collection (where the ambiguity prose lives) and before the generic Send/Cancel bucket. `test-canonical-campaigns.sh` confirms `parse-send-command.sh` resolves a message by exact `sendAliases` lookup and sets `immediate:true` whenever the resolved preset has no `requiredAttributes` (demonstrated for `mcs-practicum`, and for every other zero-attribute preset in the suite). `mcs-foundation`'s `requiredAttributes` is `[]`.
- Net effect: a message such as `send mcs to jane@example.com` (or `issue mentor coaching specialization to Jane Doe <jane@example.com>`) matches the Explicit campaign send grammar, resolves the alias to `mcs-foundation`, passes the exact Heartbeat identity gate, and — because `mcs-foundation` requires no attributes — reaches `authorized:true` and issues immediately per Dispatch Phase 1d, with no "Foundation, Practicum graduation, or Practicum partial completion?" question ever asked. This is the exact silent bare-MCS-to-Foundation mapping the new prose guard exists to prevent; the guard only reaches the New certificate collection path, not the alias table the explicit-send fast path reads.
- The aliases are registry-unique (`test-canonical-campaigns.sh`'s dedup assertion passes), so this is not a collision between presets — `mcs-practicum` and `mcs-practicum-partial` correctly do not claim `mcs` or `mentor coaching specialization`. The exposure is narrower than "any bare mention breaks": it requires the explicit `send`/`issue ... to` grammar, not ordinary conversation. But that grammar is documented in `groups/certifier/CLAUDE.md` as valid, self-authorizing input from any user in the channel, so it is a live path, not a hypothetical one.
- Fix belongs in the reviewed packet: either drop `mcs` and `mentor coaching specialization` from `mcs-foundation`'s `sendAliases` (forcing bare mentions through the ambiguity ask even on the explicit-send path), or teach the parser/prompt layer to treat those two specific strings as a reserved ambiguous token distinct from a resolved alias. Both are in-scope, in-packet changes; neither requires touching provider state.
